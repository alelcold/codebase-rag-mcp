# Devlog 2026-11-07 — Phase 1: `search_codebase` MCP server

> English first; 繁體中文版本在下方. Privacy: only the sample project in examples.

## What I did

- Created this repository: a stdio MCP server with one read-only tool, `search_codebase` ([ADR 0001](../decisions/0001-retrieval-only-tool-over-http.md)).
- Wrote the backend change it needs, `POST /search` (retrieval only), as a patch for local-codebase-rag with its ADR 0021 ([patches/](../../patches/README.md)).
- 18 tests: the MCP layer through the SDK's in-memory `Client` (real `initialize → tools/list → tools/call`), the HTTP client against a real local HTTP server.

## Problems

### Problem 1: `FastMCP` import fails on MCP SDK 2.x

- **Problem**: Every tutorial starts with `from mcp.server.fastmcp import FastMCP`; it fails on the installed SDK.
- **Error message**:

  ```text
  ModuleNotFoundError: No module named 'mcp.server.fastmcp'. This is mcp 2.x, where FastMCP was renamed
  to MCPServer (from mcp.server.mcpserver import MCPServer) and other APIs changed; see the migration guide
  at https://py.sdk.modelcontextprotocol.io/v2/migration/#fastmcp-renamed-to-mcpserver or pin 'mcp<2' to
  keep running v1 code.
  ```

- **Cause**: SDK 2.0 renamed `FastMCP` → `MCPServer`; the module `mcp.server.fastmcp` now only raises this message.
- **Fix**: Wrote against 2.x (`MCPServer`, `mcp.Client`), pinned `mcp>=2.3,<3` ([ADR 0002](../decisions/0002-stdlib-http-client.md)). Checked the 2.x API with a small spike before writing the server: tool decorator, `ToolError` → `isError: true`, argument validation, `Annotated[CallToolResult, Model]` for custom text + `outputSchema`.

### Problem 2: tool result text is escaped JSON

- **Problem**: Returning a Pydantic model put `"text": "export const ...\n..."` (escaped JSON) into the text content the model reads.
- **Cause**: The SDK serializes structured output to JSON for `content` by default.
- **Fix**: Return a `CallToolResult` with Markdown `content` and the model as `structuredContent` ([ADR 0003](../decisions/0003-markdown-text-plus-structured-content.md)).

### Problem 3: stdio smoke test — server exits before `initialize`

- **Problem**: `scripts/stdio_smoke.py` started the server as a subprocess and failed during the handshake.
- **Error message**:

  ```text
  /usr/local/bin/python3: Error while finding module specification for 'codebase_rag_mcp.server'
  (ModuleNotFoundError: No module named 'codebase_rag_mcp')
  ...
  mcp.shared.exceptions.MCPError: Connection closed
  ```

- **Cause**: `StdioServerParameters(env={...})` **replaces** the child's environment, so `PYTHONPATH` / the venv were gone and the child crashed at import. The client only sees "Connection closed"; the real error is on the child's stderr.
- **Fix**: pass `{**os.environ, ...}`. Lesson for host configs too: when a server "won't connect", run its command by hand first and read stderr.

## Concepts learned

- **stdout is the protocol**: with the stdio transport, stdout carries JSON-RPC; any `print()` corrupts it. Logs go to stderr (`logging` default).
- **Tool errors vs protocol errors**: an exception raised as `ToolError` becomes a normal result with `isError: true`, which the model can read and react to (retry, tell the user). Invalid arguments are rejected by schema validation before the function runs.
- **The tool description is a prompt**: it is all the model knows about when to call the tool and how to phrase the query. See [learning notes §3](../learning/mcp-notes.md).

# 開發日誌 2026-11-07 — 第 1 階段：`search_codebase` MCP Server

## 做了什麼

- 建立這個倉庫：一個 stdio MCP Server，只有一個唯讀 tool `search_codebase`（[ADR 0001](../decisions/0001-retrieval-only-tool-over-http.md)）。
- 寫好它需要的後端修改 `POST /search`（只檢索），以 patch 形式提供給 local-codebase-rag，附 ADR 0021（[patches/](../../patches/README.md)）。
- 18 個測試：MCP 層透過 SDK 的記憶體內 `Client`（真正走 `initialize → tools/list → tools/call`），HTTP client 對真的本機 HTTP server 測試。

## 遇到的問題

### 問題 1：MCP SDK 2.x 上 import `FastMCP` 失敗

- **問題**：所有教學都從 `from mcp.server.fastmcp import FastMCP` 開始，在安裝的 SDK 上失敗。
- **錯誤訊息**：見上方英文段落。
- **原因**：SDK 2.0 把 `FastMCP` 改名為 `MCPServer`，`mcp.server.fastmcp` 模組現在只會丟出這個訊息。
- **解法**：依 2.x 撰寫（`MCPServer`、`mcp.Client`），鎖定 `mcp>=2.3,<3`（[ADR 0002](../decisions/0002-stdlib-http-client.md)）。寫 server 前先做小實驗確認 2.x API：tool decorator、`ToolError` → `isError: true`、參數驗證、用 `Annotated[CallToolResult, Model]` 同時自訂文字與 `outputSchema`。

### 問題 2：tool 結果的文字是跳脫過的 JSON

- **問題**：回傳 Pydantic model 時，模型讀到的文字是 `"text": "export const ...\n..."`。
- **原因**：SDK 預設把結構化輸出序列化成 JSON 放進 `content`。
- **解法**：回傳 `CallToolResult`，`content` 放 Markdown，model 放 `structuredContent`（[ADR 0003](../decisions/0003-markdown-text-plus-structured-content.md)）。

### 問題 3：stdio 冒煙測試，server 在 `initialize` 前就結束

- **問題**：`scripts/stdio_smoke.py` 以子行程啟動 server，握手時失敗。
- **錯誤訊息**：見上方英文段落。
- **原因**：`StdioServerParameters(env={...})` 會**取代**子行程的環境變數，`PYTHONPATH`／venv 都不見了，子行程 import 時就崩潰。Client 只看得到「Connection closed」，真正的錯誤在子行程的 stderr。
- **解法**：改傳 `{**os.environ, ...}`。對 host 設定也一樣：server「連不上」時，先手動執行它的指令、看 stderr。

## 學到的概念

- **stdout 就是協定**：stdio 傳輸下 stdout 傳的是 JSON-RPC，任何 `print()` 都會破壞它。記錄寫到 stderr（`logging` 預設）。
- **Tool 錯誤與協定錯誤**：以 `ToolError` 丟出的例外會變成 `isError: true` 的一般結果，模型讀得到、可以反應（重試、告訴使用者）。參數不合法時在函式執行前就被 schema 驗證擋下。
- **Tool 描述就是 prompt**：模型只靠它判斷何時呼叫、查詢怎麼寫。見[學習筆記 §3](../learning/mcp-notes.md)。
